# 决策记录

倒序追加。每条写清：背景、选项、结论、代价。三家工具都读这个文件，所以**不要只把决定留在会话里**。

## 2026-10-02 — 公开版不动既有契约：泛化只在「配置层」与「可移植层」

- **背景**：`backup-dev.sh` 在本机已经跑了很久，产物布局、JSON、退出码、`last-ok` /
  `last-failure` 被三个消费方依赖：macOS 面板（Swift，`Engine.swift` 解析 JSON 与 launchd 状态）、
  已发 npm 的 DSH 插件 `dsh-dev-backup`（前缀匹配 schema、只认 `verdict ∈ {ok,bad}`）、
  以及全局 git 钩子（只依赖退出码）。同时它带着一堆本机假设：OneDrive 目标、`~/dev` 根、
  个人配置白名单（`~/.claude`、`~/.codex`、`~/.dsh`）、写死的通知标题与 FDA 提示文案。
- **选项**：A 重写一个干净的通用版本（接口自由，但三个消费方全要改，且会丢掉两年的踩坑经验）；
  B 保留全部接口，只在下面加「配置层 + 可移植层」，本机专有值搬到配置文件；
  C 只把本机版打个包发出去（把个人路径写进公共包）。
- **结论**：**B**。所有子命令、环境变量、退出码、JSON schema、产物布局、`last-ok` /
  `last-failure` 格式**逐字节保持不变**；新增的是：配置文件（KEY=VALUE）、`--config/--root/
  --dest/--logdir`、`--init`、`--version`、`schedule`，以及 `file_size/file_mtime/sha256_*/
  stamp_to_epoch` 等可移植封装。**验证方式**：把本机私有仓库那套 677 行、122 条断言的自测
  直接指向新 CLI 跑 —— 除了两条依赖 `_shared/app` 目录布局的面板本地化断言，其余全绿。
- **代价 / 后续**：字符串常量（如 schema）仍在代码里硬编码，只是加了 lint 保证它和文档一致；
  将来若要「多份配置 / 多后端」，得再开一层。

## 2026-10-02 — 归属标记 `.dev-backup-owner`：宁可不备，也不动别人的产物

- **背景**：孤儿清理（`--prune-orphans --apply`）与轮转删除的判据是「当前工作区的目标集合」。
  标签是**工作区内的相对路径**（`plugins/foo`），两台机器或两个工作区指向同一个同步目录时
  会撞名：A 机器会把 B 机器的产物当「残留」删掉。这是**数据丢失**，不是清理。
- **选项**：A 不管，文档里写「一个 DEST 只给一个工作区用」；B 给每个目标目录写一份归属标记，
  归属不符时拒绝写入 / 拒绝删除；C 在目标目录下按工作区 ID 分层（`<DEST>/<id>/repos/…`）。
- **结论**：**B**。标记文件 `.dev-backup-owner`，内容 = 工作区 ID（默认主机名 + 工作区根路径的
  指纹，可用 `WORKSPACE_ID` 固定）。三类处理：`ours` 正常；`unowned`（没有标记的老产物）
  按「大概是自己的」处理，保持与旧版本一致的行为；`foreign` 则 `--status` 只报告、
  `--prune-orphans --apply` 绝不删、备份时拒绝写入并让整轮非零退出。
- **代价 / 后续**：多了一个每个目标一份的小文件，要在兼容性文档里说明「它不是产物」。
  C 更彻底但要改产物布局（`repos/<标签>` 外面再套一层），会让所有现存产物与文档失效，不做。

## 2026-10-02 — 只读子命令严格只读；`die` 不再污染 `last-failure`

- **背景**：老版本**任何**模式都会 `mkdir -p $LOGDIR $TMP` 并可能轮转日志；`need_git` 失败时
  走的 `die` 还会写 `last-failure`。于是「看一眼状态」既产生副作用，又可能把「本机没装 git」
  写成「上次备份失败」，污染下一轮判定的输入。
- **选项**：A 维持现状，只在文档里说明有副作用；B `--status` / `--version` 不建目录不写文件，
  且 `last-failure` 只在 `backup` / `daily` 模式下写。
- **结论**：**B**。`last-failure` 的语义是「上次**备份**失败了」，只有会备份的模式才配写它。
- **代价 / 后续**：`--status` 在日志目录不可写时不再报错（它本来也不需要写）。这是行为变更，
  但方向是「更少的隐式副作用」，对外契约（退出码、JSON）不变。

## 2026-10-02 — 人读文案保持中文，机器可读 token 保持英文

- **背景**：这个工具要公开给陌生人用，那么「人类可读的输出该用哪种语言」就成了必须决定的事。
- **选项**：A 全英文；B 全中文；C 人读中文 + 机器可读全英文；D 做 i18n 开关。
- **结论**：**C**。理由：① 既有的三个消费方都不解析人读文本（面板原样贴、插件只读 JSON），
  唯一例外是面板靠子串「完全磁盘访问权限」点亮一个按钮 —— 那是中文契约，改了要同步改 Swift；
  ② reason code、upload token、JSON 字段名**本来就是英文**，机器那一侧不受影响；
  ③ 作者的另一半工具链（README、决策记录）也是中文优先，混着来反而更难维护。
- **代价 / 后续**：英文用户看 `--status` 的人读文本会吃力（JSON 与 `--help` 里的关键词是英文）。
  真要 i18n，正确做法是加 `LANG=en` 并**只**翻译人读文案，机器可读部分不许动。

## 2026-10-02 — 不引入 `warn` 档：`verdict` 永远只有 `ok` / `bad`

- **背景**：「上传中」这类中间态看起来很适合做黄灯。但已发布的 DSH 插件只接受
  `verdict ∈ {ok,bad}`，其它值会让它**整份丢弃**你的文档并静默退回旧逻辑 ——
  表面还能用，实际已经不看你的判定了。
- **选项**：A 加 `warn` 并同步发插件新版；B 不加，中间态用 `reasons[].code` 表达。
- **结论**：**B**。黄灯由消费方按 reason code 自己决定怎么显示；JSON 契约保持二值。
- **代价 / 后续**：想加必须先改消费方（面板 + 插件发版），并且要能接受「老版本会静默降级」。

## 2026-10-02 — 保留 bash 3.2 下限，可移植性只做「兼容层」

- **背景**：macOS 系统自带 bash 3.2，而 macOS 的 launchd / git 钩子通常就用它；另一侧，
  GNU 工具链上 `stat -f%z`、`date -j -f`、`shasum` 会**静默**给出空值或错值
  （bytes 变 0、产物时间退回 mtime），不是报错。
- **选项**：A 要求 bash 5 并统一用 GNU 语义；B 保留 3.2 下限，把 BSD/GNU 差异收口到几个函数；
  C 只支持 macOS，不做兼容层。
- **结论**：**B**。`file_size` / `file_mtime` / `sha256_file` / `sha256_stdin` / `stamp_to_epoch`
  几个封装，其余代码不感知平台。bash 4 专有语法（`declare -A`、`mapfile`、`${x^^}`、`local -n`）
  由 `test/lint.sh` 拦死，并在 CI 的 macOS 分支上用 `/bin/bash`（3.2）再跑一遍端到端。
- **代价 / 后续**：作者手上没有 Linux 机器，Linux 目前只有 CI 覆盖；要宣称「支持某发行版」得先
  在那上面手工跑一次 `--verify` 与 `--restore-drill`。

## 2026-10-02 — 分发：npm 为主，`install.sh` 兜底；不做 systemd timer

- **背景**：工具本身是纯 bash，不需要 Node；但「让人装得上、能升版本」需要一条正经渠道。
- **选项**：A 只发 GitHub（clone + install.sh）；B npm 包里放同一个脚本（`bin` 指向它）+
  `install.sh` 给没有 Node 的人；C 连 systemd timer 一起做。
- **结论**：**B**。npm 提供版本号、`npx` 免安装试用、以及和作者其它包一致的发布链路
  （trusted publishing + provenance）。**C 不做**：cron 已经覆盖 Linux，systemd 用户的正确
  姿势是自己写一个 unit 调 `--daily`（退出码语义一样），不必进这个包。
- **代价 / 后续**：`package.json` 里 `os` 限 `darwin` / `linux`（Windows 上没有 bash 语义）。

## 2026-10-02 — 公开版的默认值必须是「通用值」，个人约定搬到配置文件

- **背景**：老版本会三级探测 OneDrive 目录、默认收 `~/.claude`、`~/.codex`、`~/.dsh` 的白名单
  配置、通知标题写死 `~/dev OneDrive 备份`。这些在公共包里既没用又吓人（会去 tar 陌生人的 home）。
- **选项**：A 保留探测，作为「开箱即用」的便利；B 默认值全部通用化：`DEST` 必填、
  `CONFIGS=off`、不做任何云盘探测；本机约定由本机自己的配置文件提供。
- **结论**：**B**。`--status` 在未配置时输出合法的「未配置」文档（`reasons: [unconfigured]`，
  退出 2），而不是猜一个目录。
- **代价 / 后续**：陌生人第一次用必须改两行配置（`ROOT`、`DEST`）。换来的是「不会在你不知情的
  情况下把东西写到别处」。
